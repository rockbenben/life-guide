# WebDAV 同步复核（2026-11-09）

范围：版本条件、两端并发、冲突合并、断网后重试。本轮没有修改卡片、签字、合并规则、加密格式或依赖版本。

## 实际缺陷与修复

| 优先级 | 代码位置 | 发现与影响 | 修复 |
| --- | --- | --- | --- |
| P1 | `app/src/data/sync-webdav.ts` 的 fetch/push | 弱 ETag 降级到秒级 Last-Modified，无标识时无条件 PUT；无法可靠防止多端覆盖 | 读取必须获得合法强 ETag；更新使用 If-Match；创建始终使用 If-None-Match: *；不满足时报错 |
| P1 | 同文件的 304 分支 | 返回空密文并声称 unchanged，假定前次读取已合入本地；复用传输实例时，解密失败后的重试可错误报告成功 | 缓存完整密文，304 仍进入实际解密与合并，不以传输缓存代替本地提交证明 |
| P2 | 同文件的 PUT 缓存 | 成功响应缺少 ETag 时沿用旧版本；写入结果不明确时缓存也可能过期 | PUT 前清除缓存；包括响应丢失在内，下一轮必须重新读取；412 后取完整当前快照 |
| P2 | 同文件的空响应处理 | 空 200 当成文件不存在，错误走首次创建流程 | 空文件明确报错；仅 404 表示不存在 |
| P2 | `app/src/platform/http.ts` 的 nativeRequest | Android 响应头原样保留大小写，但传输层仅读取小写 etag | 原生 HTTP 响应头统一为小写 |

上述问题先新增回归测试，观察到 8 个失败用例后分别修复。旧的弱 ETag/无条件覆盖断言已按新协议更新，
没有为了保留旧行为提供降级开关。304 缺陷依赖传输实例复用；当前自动同步每轮创建实例，不能把该问题描述成已在设备上观察到的数据丢失。

## 集成验证方法

`scripts/test/webdav-sync.test.mjs` 启动本地 HTTP 服务，模拟认证、强 ETag、304、404 和原子的条件 PUT。
请求经过实际桌面 `davRequest`，未 mock 网络响应或 syncNow。每个客户端用独立 IDBFactory 和模块实例，
分别拥有数据库、时钟和同步锁，执行实际加密、解密、本地事务提交及冲突重试。

并发用例将两次 GET 挡在同一版本上再同时放行，确保发生真实的版本竞争。
设置使用不同时间戳验证最新值，删除使用墓碑，事件使用独立 eventId，不用覆盖整份文件的假同步替代实际流程。

| 验收项 | 结果 |
| --- | --- |
| 同时首次创建 | 条件创建竞争后重读、合并、重试；最终保留两端事件，后续读取两端收敛 |
| 同版本并发更新 | 基于同一 ETag 竞争，冲突后重试；事件、设置和删除标记收敛 |
| GET 断线 | 报失败，不记成功时间；本地修改保留，下轮可恢复 |
| PUT 写入前断线 | 合并后的本地数据保留；重试后远端同时包含两端记录 |
| PUT 已写入但响应丢失 | 不误报成功；重读远端后恢复，不重复创建事件、不丢改动 |
| 连续冲突 | 两次推送均冲突时明确失败；本地合并结果保留，下一轮可恢复 |
| 解密失败后 304 | 再次失败而非误报成功；不改成功时间，不覆盖远端 |
| Android 大小写响应头 | 原生桥返回 ETag 时，平台层正确提供 etag；属于桥接口测试 |

## 边界与维护

WebDAV 服务必须提供强 ETag，并正确、原子地执行 If-Match / If-None-Match。
客户端发送条件头不能修复服务端“忽略条件仍覆盖”的实现，本地模拟服务验收也不等同于验证某个真实网盘。
本轮没有连接用户网盘，没有在 Android 实机、坚果云或 Nextcloud 上做往返同步，不声称已完成这些外部验收。

自动同步仍沿用既有的五分钟检查间隔与失败冷却；手动“立即同步”不受冷却限制。
本轮验证的是失败后的实际同步重试流程，没有改动自动调度策略。

后续若希望支持只有弱 ETag 的服务，需要服务端提供可证明安全的原子版本或锁机制，不能恢复时间戳降级或最后写入覆盖。
本轮增加的协议与集成用例应作为回归门禁保留；若需要回滚，保留强条件写入保护，避免直接恢复原有无条件覆盖行为。
