# 依赖安全复核（2026-11-09）

范围是上一阶段留下的 19 项 npm 审计告警。19 是受影响包的数量，实际涉及 5 个底层安全公告。
本轮不改业务、卡片、签字与正式密钥，不使用 `npm audit fix --force`，不为降低告警数降级工具。
作者已暂缓需要正式密钥和真机的 Android 验收，该项不作为本轮依赖修复的退出条件。

## 处置结果

官方 registry 的全量审计从 **14 moderate、5 low** 降为 **4 low**；moderate、high、critical 均为 0。
解决了 15 个受影响包条目。留下的 4 项来自同一个尚无修复版的 `deepmerge` 问题。
保留完整审计结果，不屏蔽包、不添加忽略公告，也不把 npm 的生产/开发依赖分类等同于实际攻击面。

## 五个底层问题的实际影响

### 1. UUID：工具中的调用不触发已知漏洞，但可安全升级

[安全公告 GHSA-w5hq-g745-h8pq](https://github.com/advisories/GHSA-w5hq-g745-h8pq)
描述的是 v3/v5/v6 接收调用方提供的输出 buffer 时缺少边界检查。
已核对 `xcode/lib/pbxProject.js` 的 `generateUuid`：只调用无参数的 `uuid.v4()`，
再删除连字符、截取 24 个字符并转大写；项目中没有公告要求的 buffer 调用条件。

仍将 `xcode` 的 UUID 从 7.0.3 定向升级到 **11.1.1**：该版本有修复且保留 CommonJS，
满足 `xcode` 的 `require('uuid').v4()` 接口。没有直接替换为已移除 CommonJS 的后续主版本。
通过真实 iOS 工程读取、100 个 ID 的格式与唯一性、添加分组后保存/重读验证；源工程未修改。

### 2. Minimatch：保留项目所需的匹配语义

[安全公告 GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249)
涉及构造的 glob 模式导致资源放大。项目的匹配模式来自版本库中的打包、lint 和 PWA 配置，
普通用户的卡片输入与同步内容不作为 glob 模式进入这些工具。

受影响的 9.x/10.x 分支升级到 **11.0.5**。`overrides` 以消费包和 `>=7 <11` 限定范围，
没有把所有 `minimatch` 都替换掉：旧版 ASAR/glob 仍使用不在该公告范围内的 3.x 可调用导出，
`filelist` 保留其 5.x。最终 `npm ls --all` 无 invalid/extraneous 错误。

验证了桌面真实 `files` 配置的包含/排除、universal 所用的命名函数与 `matchBase`、
CLI 所用的 `minimatch.Minimatch` 构造器，以及 Windows 打包。
本机未验证 macOS 原生双架构合并，接口测试不冒充该平台的完整构建验收。

### 3. KaTeX：应用运行时未使用，修复文档工具链

[安全公告 GHSA-238p-pmpm-9mq7](https://github.com/advisories/GHSA-238p-pmpm-9mq7)
要求已有原型污染或可影响 options 原型，并将数学渲染输出插入页面。
`markdownlint/lib/micromark-parse.mjs` 只导入 `math` 语法扩展；KaTeX 是该包导出依赖，
应用页面使用 `marked`，没有这条数学 HTML 渲染链。

仅将 `micromark-extension-math` 下的 KaTeX **0.16.47 → 0.18.2**。
验证了行内/块级公式 lint、数学扩展 HTML 接口及默认不生成 `javascript:` 链接，
并对全库 Markdown 重新检查。

### 4. Glob：当前调用不用取消信号，升级后核验预缓存完整性

[安全公告 GHSA-3g3m-2fjr-6pw4](https://github.com/advisories/GHSA-3g3m-2fjr-6pw4)
涉及取消/超时后仍继续遍历目录。
`workbox-build/build/lib/get-file-details.js` 调用 `globSync`，传入 `cwd/follow/ignore`，
没有传 `signal`，不存在“依赖取消信号来限制扫描”的使用方式。

将 Workbox 的 **glob 11.1.0 → 14.0.4**，保留其使用的同步扫描接口；项目的 Node 26 满足新版本要求。
仅定向覆盖 Workbox 中受影响的版本，没有将 ASAR 的旧 glob 7 替换成不兼容接口。
通过预缓存扫描集成测试、生产构建和前后清单对比：仍为 **127 项、106 张图片**，
归一化 JS/CSS 文件名中的内容哈希后，资源 URL 集合一致。

### 5. Deepmerge：保留告警，等待上游修复

[安全公告 GHSA-gcqx-w48m-w2h4](https://github.com/advisories/GHSA-gcqx-w48m-w2h4)
指出合并恶意源对象时可能污染返回对象的原型，当前没有修复版。
已核对安装的 `@rollup/plugin-node-resolve/dist/cjs/index.js`：唯一调用是
`deepFreeze(deepMerge({}, defaults))`，`defaults` 是模块内写定的数组、字符串和布尔值。
外部 `opts` 后续用对象展开合并，不经过这次 `deepMerge`；卡片、备份和同步负载也不进入该调用。

保留 **deepmerge → node-resolve → workbox-build → vite-plugin-pwa** 四项 low。
不降级到审计范围之外的旧版本，不替换库、不维护临时 fork。
上游发布修复版，或解析插件改变为合并外部数据时，重新评估并升级。

## 验证与回滚

跨上游版本范围的覆盖由 `scripts/test/dependency-overrides.test.mjs` 守住消费方接口，
并配合实际构建、全库检查验证。锁文件整理包含依赖去重和允许范围内的补丁更新
（包括 Vite 8.3.5 → 8.3.6），没有降级直接框架或工具。

去重期间发现 `@capacitor/core` 被 peer 解析到 8.6.0，而原生 SDK 仍为 8.5.3。
为避免本轮顺带升级需设备验证的 SDK，另加 core 8.5.3 的版本约束，恢复本轮前的原生组合。
集成测试同时检查应用、通知插件和两个原生 SDK 解析到同一个 core 实例且版本一致。
这项约束与审计数量无关，后续升级 Capacitor 时需将三个 SDK 一起升级并移除或更新它。
`cap sync` 产生的通知插件路径调整来自依赖去重，指向锁文件中实际的 hoisted 路径。

全量验收复现了同步并发测试偶发的响应体重复读取错误；调整为每个请求返回后立即读取其响应，
不跨越后续请求保留响应流。请求仍然在 `Promise.all` 中并发，保留“恰有一个成功”和
“全部冲突响应等于赢家密文”的断言。定向测试连续五轮通过后再执行全量测试；未修改同步服务逻辑。
